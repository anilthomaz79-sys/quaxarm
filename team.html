How we run a programme

Every engagement follows a full project lifecycle. We align each phase to widely adopted industry standards — we do not treat security, quality, or handover as extras at the end.

1. Discover

Scope, stakeholders, constraints, and success measures. Requirements and risk are captured so the programme has a baseline — not a vague ambition.

2. Design

Target architecture, security and identity design, and data handling. We work to security-by-design and privacy-by-design principles, and to Microsoft Cloud Adoption Framework / Well-Architected guidance where the estate is Azure.

3. Build

Iterative delivery with a clear backlog, code review, and environments that match production intent. Application work follows OWASP-aligned secure coding; changes are versioned and traceable.

4. Assure

Functional testing, security verification, and user acceptance before go-live. Defects and residual risk are visible — not buried in a last-week scramble.

5. Release & operate

Controlled release, runbooks, and handover. Operations follow ITIL-aligned change, incident, and problem practices so the system can be supported after the project team steps back.

Across the lifecycle we align to ISO/IEC 27001 information-security controls, NIST Cybersecurity Framework thinking, GDPR-minded data protection, and ISO 9001-style quality discipline (documented scope, reviews, and a definition of done). Where clients already hold certifications, we fit our artefacts to their existing control framework rather than inventing a parallel one.
